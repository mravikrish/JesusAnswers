# JesusAnswers API

Spring Boot 4 · Java 21 · PostgreSQL · Claude (`claude-opus-5-5`) · Firebase Auth

## Endpoints

| Method | Path | Auth | Purpose |
|---|---|---|---|
| POST | `/v1/answers` | optional | Scripture refs + encouragement + prayer, in the requested language |
| GET | `/v1/journey` | required | The signed-in user's journey (latest 500) |
| PUT | `/v1/journey/{id}` | required | Upsert one entry (id generated by the app → offline-safe retries) |
| DELETE | `/v1/journey/{id}` | required | Delete one entry |
| DELETE | `/v1/me` | required | Delete account + all entries |
| POST | `/v1/reactions` | none (`X-Install-Id`) | Heart / unheart / prayed / listened for one prayer, story, chapter or saying |
| GET | `/v1/counts` | none | Shared counts per item, plus how many people prayed today (worked out at most every 5 minutes) |
| GET | `/v1/circles` | none (`X-Install-Id`) | The prayer circles this install is in |
| POST | `/v1/circles` | none (`X-Install-Id`) | Start a circle `{name, memberName}`; answers with its invite code |
| POST | `/v1/circles/join` | none (`X-Install-Id`) | Join with a code `{code, memberName}` (20 tries an hour) |
| GET | `/v1/circles/{code}` | members | The circle: members and the last 60 days of requests |
| POST | `/v1/circles/{code}/requests` | members | Share a prayer request `{text}` |
| POST | `/v1/circles/{code}/requests/{id}/prayed` · `answered` · `report` | members | I prayed · God answered (asker only) · report |
| DELETE | `/v1/circles/{code}/requests/{id}` | asker or owner | Delete a request |
| DELETE | `/v1/circles/{code}/members/{id}` | owner | Remove a member, with their requests; they can't rejoin |
| POST | `/v1/circles/{code}/leave` | members | Leave, taking your requests with you |
| GET | `/v1/voice-sources` | none | Where the app downloads natural voices from (`VOICE_SOURCES`) |
| GET | `/actuator/health` | none | Health check |

Auth is a Firebase ID token: `Authorization: Bearer <token>`.

## How an answer is made

1. Prompt = **system prompt** (pastoral guidelines + the 60-verse theme index; identical on every request, so it's
   prompt-cached for an hour) + **user message** (language, mood, kind, and their words fenced in `<user_message>`).
2. Claude returns structured JSON (`ModelReply`): themes, verse refs, encouragement, prayer, crisis flag.
3. The server **keeps only verse refs that exist in the corpus**. The app renders verse text from its own bundled
   files, so Scripture is never invented or misquoted.
4. Crisis = Claude's flag **or** the deterministic keyword check (`Safety`, all 11 languages). On crisis, Psalm 34:18
   leads and the app shows helplines first.
5. If Claude fails, times out, or declines, the API returns **503** and the app answers offline instead.

Server-side refusal fallbacks are enabled (`fallbacks: "default"`), so if a safety classifier declines a request,
Anthropic re-runs it on its recommended fallback model rather than leaving the person with nothing.

**Cost**: about 3K cached input tokens plus about 1K output tokens per answer. At Opus 5.5 rates ($4/$20 per MTok,
cache reads $0.20), thinking tokens included, that comes to roughly $0.02–0.05 (₹2–4) per answer. Set `CLAUDE_EFFORT=low` or `CLAUDE_MODEL=claude-sonnet-5-5`
to trade quality for cost or speed. Measure on real questions in each language before switching.

## Privacy

- Journey text (question, encouragement, prayer) is **AES-256-GCM encrypted** in the database (`JOURNEY_ENCRYPTION_KEY`).
- Only the Firebase uid is stored; no email or phone.
- Shared counts store no account and no content: only the item, a day, and a salted hash of the app's random
  install id (`COMMUNITY_SALT`). Prayed / listened count once per install, item and day; reactions are rate-limited.
- Prayer circles have no accounts either: a member is the same salted install-id hash, plus the name they chose.
  Requests are encrypted like the journey, only members can read them, and they're deleted after 60 days, when
  the asker leaves, or when 3 members (or half the others) report them. Non-members get 404 for any circle.
- User messages and replies are **never logged**; only token counts are.
- Host the database and API in an Indian region (e.g. GCP/AWS Mumbai) to keep data in India under the DPDP Act.

## Run locally

```bash
# 1. Database (either a local PostgreSQL…)
psql -U postgres -c "create user jesusanswers with password 'devpassword';"
psql -U postgres -c "create database jesusanswers owner jesusanswers;"
#    …or Docker:  docker compose up -d   (then DATABASE_URL=jdbc:postgresql://localhost:5434/jesusanswers)

# 2. Config: copy .env.example → .env and fill it in, then export it.

# 3. Run (Flyway creates the tables)
./mvnw spring-boot:run

# 4. Try it
curl -X POST localhost:8080/v1/answers -H 'content-type: application/json' \
  -d '{"question":"నాకు ఉద్యోగం పోయింది, భయంగా ఉంది","lang":"te","kind":"question"}'
```

The app talks to it with `flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8080`
(`10.0.2.2` is your PC from the Android emulator).

**This PC runs Avast Web Shield**, which intercepts HTTPS. Java doesn't trust Avast's certificate, so prefix Maven
with `MAVEN_OPTS="-Djavax.net.ssl.trustStoreType=Windows-ROOT"`. The running API needs the same flag for its calls to Claude.

## Tests

```bash
./mvnw test
```

These are unit tests and need no database or API key. They cover corpus integrity in all 11 languages, verse-ref
validation, crisis handling, the exact Claude request (effort, structured format, prompt caching, fallbacks),
encryption, and rate limiting.
